# 작업 detail

A work card (`#/cards/<id>`) or a worker run outside any card (`#/runs/<id>`) opens its detail in the one detail frame: title, state and time, what it is doing now, the to-dos it covers, the worker runs it started (dimmed, one line each) and its comments, one line each.

## Platforms

- `web`: shipped.
- `mac`: planned (M1).
- `iphone`: planned (M1).

## Intended behavior

- A card or a run opens in the one detail frame (lina-app#142), wherever it is chosen: the right-hand pane beside the list at desktop width (it scrolls on its own, so it opens where the owner is looking however far down the list they chose it; the window, the toolbar and the menu never scroll away), a sheet rising from the bottom over the list at phone width, with `닫기`. The tab, the header and the list stay as they were. Back closes the frame; the list is at the scroll it had and the chosen row stays highlighted. Opening and closing the pane never moves the list at desktop width: its scroll is the same before, while and after, however its rows wrap when it narrows (lina-app#153). At desktop width the pane's head has `닫기` at its top right (lina-app#161): it and Esc close the pane at once, however many records were opened in it one after another (A, then B from the list: one press closes it, never back to A, lina-app#166), the list keeps the scroll it has, and focus goes back to the row that opened the shown record; Esc typed while a Korean syllable is being composed, or while the bell's list is open, is theirs. A frame opened in 대화 keeps its back control to the agent's card instead. Nothing in the frame is cut, at 390 or 1280 (lina-app#161): a line that would run past it, the card's own name included, wraps at a word instead of ending in `…` (src/detail-qa7.test.tsx, tests/detail-qa7.spec.ts).
- The head reads the title and `진행 중 · 시작 n분 전` (or the stopped, waiting or done line). A stopped card or run reads the same words and the same time as its 중단됨 row on the home, from one function (`stopReason` in `src/model/stop-reason.ts`, the time from `cardTime`): `중단됨 · <owner> 확인 필요 · 3시간 전` on both, never `중단됨 · 결정 필요` on one and `확인 필요` on the other. The head reads the state of the row that was pressed (the list's snapshot) until the next refresh moves both, even when the card's detail, read later, already says another (lina-app#157).
- A stopped card says why (lina-app#157, lina-app#156): the row's stop words follow `중단됨` in the state line (`결정 대기 · <ask>`, `피드백 대기 · <ask>`, `<agent> 검토 대기`, another reason's own word), so no second line repeats them. Only where the state line is `중단됨` alone (a card the core only reads that waits on the owner) or no row is known, one grey line under it says `결정 대기 · <ask>` / `피드백 대기 · <ask>` by the core's `reason`, else the reason's word, else `이유 없음`. When the newest of its comments is the owner's, made after the stop, one more line reads `결정 기록 있음 · 상태는 아직 중단됨`. The owner's `다시 시도해 주세요.` is no decision (lina-app#211): while the card's row reads `<agent>에게 요청함` (actions.md, Retry), one line under the head reads the same words (`requested-since-stop`), and `결정 기록 있음` counts only the owner's other comments; a card with both after the stop has both lines. A request older than the stop reads neither.
- A stopped card that waits on the owner has the place to answer it under its head: a `답 달기` field and `보내기`, sent as the answer to its question (the same as from 수신함). While `보내기` cannot send, one grey line under it says why (`글 입력 대기`, `보내는 중`). On a to-do's or a goal's decision, once `보내기` is pressed and for as long as the toast `답함 · 되돌리기` is up, the head keeps the two lines of the row that was pressed (`목표 › 작업` and the question), the state line reads `답함`, and the answer just sent stands where the question box stood, with no field; `되돌리기` brings the box and the field back, holding the answer that was not sent (lina-app#166). A card stopped on anyone else has none. A work card's head reads the name of the row that was tapped (lina-app#153): the title its row reads (its goal's when the row leads with it), else its checked title, or its own title until the checked one is written — only while that own title passes the app's raw-text rule — shortened to the row width. When the card's own title differs from that name it is the grey line under the head's state line, and the `목표 · <goal>` line shows only when the head does not already read the goal. The kind is never the title (lina-app#149) and shows only when known: the core serves no kind of a card, so a card nothing names a kind for shows no kind, never `코드` (lina-app#153). With no title at all the head reads `제목 없음` in grey. A run outside any card without a checked title reads its row's title the same way.
- A read-only card (`readOnly: true`, every card and goal the core serves from the Hermes board, lina#481; the core refuses its writes with 409) has no write control at all (lina-app#149): no `답 달기`, `보내기`, choice buttons or `다시 시도`, on its detail or its row. One grey line under its head says it cannot be changed here, naming no board (lina-app#153): `읽기 전용 · 여기서는 바꿀 수 없음`. Its question still shows as a `결정 필요` box, but its state line makes no claim that the owner must act: only the state word and the time, no `확인 필요` or `피드백 대기`, which show only where an answer box exists. A to-do of the owner's own record stays writable.
- lina-app#171: a stopped card says its state once. The run box has no line of its own repeating `중단됨 · <why>`; the head's state line and the grey line under it are the only place. A reason longer than the row says (the row cuts it at a word to 30 letters with `…`) is said whole under the state line, wrapped, never cut: the words before it (`결정 대기`) on the grey line, then the reason (`stop-reason`). A reason the core cut in its `ask` reads from the work inbox's `blockReason`, through the comments' fold (ids, references and hashes cut; a sentence with no Hangul, an English sentence or a banned word left out). A decision or feedback stop with no sentence of why reads `결정 대기 · 이유 기록 없음` / `피드백 대기 · 이유 기록 없음`, as its row; an internal word in `blockReason` (a status name) is no sentence.
- lina-app#171: a read-only card that waits on the owner (decision, feedback or the owner's check) adds one grey line under `읽기 전용 · 여기서는 바꿀 수 없음`: `답할 곳 · <agent> 대화`, the agent's name a link to that agent's conversation (`#/talk/<agent>`), drawn in the app's link colour (accent, 4.5:1 on the page and the panel in dark, lina-app#174), not the grey of the line. Only when the card names an agent the app knows; otherwise the read-only line stands alone. It is text and a link only: no write is added.
- lina-app#171, #174: a card has one `댓글` section. Its `댓글` box holds the card's comments and the comments between rounds that only its worker runs' record holds, once each, newest first; the card's `기록` has no comment block. A record comment the card also holds (a machine notice the box leaves out too) is never drawn. A worker run's own page has no `댓글` box, so its record's comments between rounds stay `댓글` blocks there.
- lina-app#171: the detail of a folded line (`<title> ×N` in `완료`) lists every card of the line under `묶인 작업 N건`, one `<time> · <state word> · <sentence>` line each, the opened card first, then newest first, each the link to its card.
- An old done card the core keeps no history for (`detail: false` on its list row: no runs or comments in its detail) shows one line, `기록 보관 안 됨`, under its head instead of an empty frame.
- A question the card asks the owner (from the work inbox) shows on top as a `결정 필요` box: the sentence, then agent, `결정 대기` (its 수신함 row's word, lina-app#179) and age.
- Below the boxes and above the comments, `기록` is the run's own timeline (lina#201), on a card (its worker runs' records together) and on a worker run's page. It is the card's one round list: one block per round, newest first by the time its head reads (lina-app#149; its rows newest first too), headed by one history line `<time> · <outcome>[ · <result sentence>]` with no round number (lina-app#61, #123, #142; `어제 23:41` when not today): the time is a going round's start and an ended round's end (its start when the end is not on record), the outcome `진행 중`, `검토 통과`, `검토 필요`, `중단됨`, `완료` or `완료 기록 없음`, then the round's result line, cut to its first sentence, when it left one a person may read (`02:11 · 검토 통과 · 병합된 변경 41개를 모음`). There is no second result line. On a card each round's head is the keyboard-reachable link to that round's worker run (`#/runs/<id>`). Rows read oldest first, one event per line in the form `<time> · <one sentence>` (`14:05`, `어제 23:41`, `11월 9일 08:10`; lina-app#123, #128): the run's sentences in the label colour, tool steps as one dim `도구 사용 n번`, the owner's comments with author and time, a sentence said n times in a row once with `×n`; a round whose start is not on record opens with one dim `시작 기록 없음`; a round's result line follows its rows (`결과`); a comment made between rounds is its own block. A sentence or a result line that would show raw English, a path, a command, an id or a run number is left out, with no placeholder; a round left with no rows still shows its head. A comment that would show raw text stays as its folded entry (`접힌 댓글`). Each block folds; its open state and the scroll survive the record's refetch on its run's `worker` change event. A failed read shows one line `읽기 실패: 기록` in its place, and the rest of the detail keeps working.
- A card's detail is read when the card opens, never at the first load (lina-app#100). While it is read the card shows its list row at once: the head (title, kind, state and time) and `지금`, with `불러오는 중` below; the boxes fill in when it answers. The history (`기록`) and `댓글` are drawn once (lina-app#217): the records of its worker runs are read only after the detail names them, so until every one of them has answered, that one `불러오는 중` line stays in their place, never the worker runs' box drawn from the detail alone (`이전 기록 N건`) that the records then redraw longer. A record that lands alone meanwhile (an event named it) keeps that line too. Once drawn, a record a new worker run brings adds to them in place; opened again, the card draws them at once.
- A worker run a card started is not on the board's list (the core lists only runs outside any card); its round's head still opens its own page: the card it belongs to and its timeline. Opened on its own before its card (a reload or a link from elsewhere), the run's record names its card (`cardId`) and the page reads that card's detail: meanwhile it shows the kind word, model line and `불러오는 중`, never a round outcome it cannot know yet; then the card row and the timeline as when opened from the card. A worker run with no record to read (an older run the core has none for) cannot name its card before the card opens: its page keeps the kind word and one `읽기 실패: 기록` line, never `찾을 수 없음`.
- `지금` shows the now line while it runs.
- `할 일` lists the to-dos the card covers, each with a round mark that only shows its state: the card cannot change a to-do, so the mark is no control and has no action name (no `<title> 완료로 표시`); a done one reads `완료` to a screen reader (lina-app#128).
- The worker runs' box is headed `기록`, the run history's one name whether the card runs or stopped (lina-app#179). It stands only while the record is not shown (no record yet, or with no head of its own under the `기록` box's error line when its read failed, so the worker links never disappear). It lists the worker runs the card started, one line each, `<time> · <state word>`: newest first (lina-app#157): when it started (first seen), then `진행 중` while it beats, else how its round ended (`완료`, `중단됨`), else `결과 누락` (lina-app#166, the screen words table: an ended run with no result); never `코드 작업`, and never the card's title again on every line (the head carries it, lina-app#142). They never show as their own card elsewhere. Each run of rounds whose own line may not show is one folded row `이전 기록 N건`, their heads and worker runs inside, never one `이전 기록 1건` row per round (lina-app#161). A stopped card says why above that box, one grey line `중단됨 · <reason word>` (`결정 대기`, `피드백 대기`, another reason's own word, else `이유 없음`), since its rounds may all read `완료` (lina-app#161).
- A to-do the card covers is checked only when it is done; a card whose run is still going covers open to-dos.
- `댓글` shows each comment as one history line, `<time> · <first sentence>`, newest first like every history (lina-app#149). No markdown emphasis marker (`**`, `*`, `~~`, `__`) reaches a history line, a round's head, a comment or a question: the marker goes and the words stay, and an entry that is only markers and spaces is no row at all, never an empty line or a folded one (`plainText` in `src/model/plain.ts`, lina-app#166). Every history sentence (a card's comments, a goal's or a to-do's 기록, a round's line) first goes through the fold titles go through (lina-app#157): ledger, goal, card and to-do ids (`G117`, `t_…`, `T7`), issue numbers and hashes are cut with the bracket around them, a who-and-when bracket (`(<agent> 16:5x)`) is cut, and a sentence holding a word the screens never use (`장부`) is left out; ids (card, run, to-do and issue numbers, `rc=1`), hashes, paths, commands and addresses are left out of the sentence, a sentence with an English word or one starting inside a word or a number (`.5초`) is skipped whole, and it is cut at a word end within 60 characters with `…`, before a bracket the cut would leave open; the author is the line's tooltip. What is left must still read as a sentence (lina-app#197, #222, `sentenceMayShow` in `src/model/fold.ts`, the one rule for history lines, folded comments and titles, the card, goal and run details and the inbox: no start inside another sentence, no open end, no hole, no Latin letter or ref): no empty bracket pair or bracket left open or closed alone, no punctuation standing alone or doubled (`,.`), no separator, `|` or lone particle at either end, no start on a closing quote, a particle or a fragment; a list number (`1)`) before it goes. When the first sentence does not read, the next one that does is the line; when none does, the row keeps its own word (`접힌 댓글`, the round's outcome) or is not drawn. A machine notice (by `kanban-dispatcher` or `lina-worker`, or opening with a tag of words alone such as `[받음]`, `[대기 충족]`, `[현황]`) is no line. A bracketed tag that opens a sentence with a role and a time (`[<role> 02:21 결정]`) is cut off and the sentence after it is the line; a time of day inside a sentence (`22:45`) is left out, so a line shows only its own time; a line that is only the state word of the line before it (`완료` again and again) is no line (lina-app#153). A run of comments with no readable word left is one `접힌 댓글` line (`접힌 댓글 n건`). A comment row in `기록` is the same one line, and comments made one after another between rounds are one `댓글` block.
- A name cut inside a sentence leaves no particle standing alone (lina-app#207): when its particle was written apart (`152번 <name> 로`, `번들 <path> 를`), the kind of thing it named stands in with the particle in that noun's form (`항목으로`, `폴더를`, `파일을`, `커밋을`, `카드가`, `이슈라`; `ROUND15_WORD.nameKind` in `src/words.ts`), so the sentence keeps its meaning; a sentence that opens on the name has nothing of its own left and goes whole, as before (`src/model/fold.ts` withKinds, `src/model/timeline.ts` readable). An ISO time a machine wrote into a comment (`=2026-11-16T03:30+09:00`) reads as every time on the screens, `11월 16일 03:30` on the device's clock, and the `=` its cut key left goes with it (`timesInText` in `src/time.ts`); after its date, its time of day stays on a history line.
- A cut never leaves a hole (lina-app#218), by one rule for history lines, folded comments and titles (`cutLeavesHole` in `src/model/fold.ts`, used by withoutRefs, withoutLatin and readable).
- One rule decides every drawn history line, folded comment sentence and title (lina-app#222, `sentenceMayShow` in `src/model/fold.ts`): a sentence is drawn only when it (a) starts on a word, not a separator, an arrow, a particle alone, a bare number with its unit (`5초.`) or a list's number alone (`2.`), (b) ends closed, not on `:`, `|`, a separator or an opening bracket, with every bracket and quote it opens closed, (c) has no hole, no particle apart from its noun (`파일 를`) and no modifier with no noun after it (`노출된.`), and (d) holds no Latin letter or ref: an English word, a product name, `PR`, a round label (`S2`, `N1·N2`, `D1~D7`), `rc 0`, `#12`. A comment's line is its next sentence that passes; a comment with none is one of the 접힌 댓글 run. The split never cuts after a list's number (`순서는 1. 빌드`), and a dot inside a number, a version or a file name (`0.5`, `1.2.3`, `a.md`) is no sentence end (`sentencesOf`). A folded comment cuts the identifiers a history line cuts (a path, a command, a short id) before the rule, so both read the same sentence. A particle glued after a bracket the cut took whole goes back onto the word before it (`관문(<ref>)을` reads `관문을`), and a bracket that keeps words keeps its place (`저장소(…)에서`). A sentence whose cut left a modifier with no noun (`새 <hash>로 충족됨`), a topic or an object with no predicate (`새 판은 <hash>.`), or a pair mark or a list's `·` beside a cut between two words (`#12~#14는`, `#12·#13과 파일이`) is not drawn: the line takes the next sentence of the comment that reads, else the comment is one of the `접힌 댓글 N건` line's (a row that does not open, so the cut text is not on screen), and a title so cut is no title. A colon with only a bracket after it goes (`앱 반영: (<n>회차 앞)` reads `앱 반영 (<n>회차 앞)`). A line that leads a list in (it ends in `:`) reads with its first item, `<lead-in>: <item>`, the item's mark dropped, the other items lines of their own; with no item after it the lead-in goes (`withLeadIns` in `src/model/plain.ts`, in plainText, foldedText and firstSentence), so no drawn line ends in `:`.
- One rule orders every history: by time, newest first (lina-app#153), the worker runs under a round too (lina-app#157). A round's own line that may not show is folded with the rounds next to it into one `이전 기록 N건` row (lina-app#161): a folded block is named `댓글` only when it holds comments. A card's worker runs that serve the same record show each round and each comment once, and a round with nothing in it but the outcome of the round before it is no block.
- A run outside any card opens at `#/runs/<id>` with its own state and the to-do it takes on.
- A worker run's page names the model that run used once, under its head, by the plain name the model list gives it, with its effort (`<name> · 보통`). A run that started on the fallback model ends the line with `대체 모델` (`<name> · 높음 · 대체 모델`). A model the list names only by an id is an alias (`model-a`, `model-b`) and draws no line (lina-app#128); neither does a run with no model. The rounds of that page's 기록 draw no model line. The settings revision is not shown.
- On a card's 기록, each round shows its own run's model under the round's head, dim, once: the worker run that round was, the same one its head opens. A round whose run has none shows nothing. A comment block shows none.
- Only boxes that add something are drawn.

## Sub-features

- `card-head` shows the name of the row that was tapped (never a kind word), the card's own title under it when it differs, the kind only when known, the row's state and time, why a stopped card stopped, and `읽기 전용 · 여기서는 바꿀 수 없음` on a read-only card
- `card-now` shows what it does now
- `card-runs` dims the worker runs it started
- `run-detail` opens a run outside any card, or a card's own worker run
- `run-model` names a run's model once under its head; a card's 기록 also names each round's own run
- `card-timeline` shows the run's own record round by round, one `<time> · <sentence>` line per event; a finished run with no record lists its start and its result line

## How to get to it (user POV)

- Choose a card on 진행 중인 작업, 완료, an agent screen or a goal page.
- Choose a `결정 필요` row in 수신함 whose small line reads `목표 › 작업`: it is the card's question; choosing it opens the card in the detail frame with the question box on top and the place to answer it.
- Choose a 검토 필요 row in 수신함 for a run.
